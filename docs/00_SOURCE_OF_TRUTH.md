# 00 — مصدر الحقيقة

## نطاق الوثيقة

هذه الوثيقة تحدد أي مصدر نثق به عند بناء Flutter.

### ترتيب السلطة

| المستوى | المصدر | الاستخدام |
|---|---|---|
| 1 | `docs/` Canonical | السلوك والقرارات التنفيذية |
| 2 | `contracts/` | DB/API/Plans |
| 3 | Reference screenshots | الشكل والتوزيع |
| 4 | source snapshot الأصلي الذي تم تحليله | التحقق من التفاصيل |
| 5 | `archive/` | التاريخ فقط |

## لماذا تم إنشاء طبقة Canonical؟

المصدر الأصلي يحتوي عددًا كبيرًا من ملفات Release / Refactor / QA عبر عدة أجيال. هذا مفيد كسجل تاريخي لكنه غير مناسب ليكون تعليمات مباشرة لوكيل يبني Flutter، لأن بعض الملفات:

- تتحدث عن مراحل قديمة.
- تحتوي أسماء متعارضة.
- تستخدم أرقام إصدارات قديمة.
- تصف انتقالات مؤقتة.
- تخلط Current وTarget وHistorical في الملف نفسه.

لذلك تم فصل **الحقيقة الحالية** عن **سجل التاريخ**.

## هوية المنتج

- الاسم التجاري: Mivent / مايفنت.
- النسخة المرجعية: 2.14.21.
- المنصة الحالية: Web/PWA.
- المنصة الهدف: Flutter.
- الاتجاه: Arabic RTL.
- النموذج التشغيلي: Local-First.

## ما الذي لا يجب حمله حرفيًا من الويب؟

- DOM IDs.
- أسماء ملفات JavaScript.
- أسماء `localStorage`.
- Service Worker كمعمارية Flutter.
- Browser install banners.
- أي cache compatibility layer خاص بالويب.

يتم نقل **المعنى والسلوك** وليس تفاصيل DOM.

## المبدأ الأهم

Flutter لا يجب أن يكون نسخة من فوضى source structure القديم.

يجب أن يكون تنفيذًا نظيفًا لنفس Domain والسلوك والعقد.
