# 13 — معايير القبول

## A. التطبيق

- يفتح مباشرة إلى آخر سياق محفوظ.
- يعمل بدون اتصال.
- RTL كامل.
- النصوص العربية سليمة.
- لا توجد شاشة بيضاء عند غياب الشبكة.

## B. التقويم

- الانتقال بين الأشهر.
- زر اليوم يعيد للشهر الحالي.
- حالات الأيام صحيحة.
- لا تنتقل حجوزات شهر إلى شهر بسبب رقم اليوم فقط.
- فتح يوم يعرض حجوزاته الفعلية.

## C. الحجز

- إنشاء حجز.
- تعديل.
- إلغاء.
- حجز مؤقت.
- انتهاء الحجز المؤقت.
- منع double booking وفق إعداد الشركة.
- ربط/إنشاء العميل.
- حساب المبلغ والمتبقي.
- حفظ ذري.

## D. العملاء

- البحث.
- مطابقة الاسم والهاتف.
- صفحة العميل.
- حجز العميل.
- الحركات المرتبطة.

## E. المالية

- قبض.
- صرف.
- عربون.
- دفعة.
- تسوية.
- استرجاع.
- تصحيح مع Audit.
- عدم حذف الحركة ماليًا.

## F. الخطط

- BASIC.
- PLUS.
- SUPER.
- ULTRA.
- حدود العدادات.
- الحدود الدورية.
- الإخفاء/المنع في العميل.
- لا تعتمد الواجهة كسلطة أمنية.

## G. Backup

- إنشاء نسخة.
- فحص.
- استعادة.
- checksum.
- عدم إدخال session secrets.
- عدم إنشاء Sync commands بسبب Restore فقط.

## H. Sync

- Push batch.
- idempotency.
- conflict.
- pull cursor.
- no queue on pull.
- no queue on bootstrap.
- resume after interruption.

## I. الأداء

- calendar scroll.
- booking list.
- customer search.
- finance list.
- restart.
- large local dataset.

## J. الجودة

قبل إنهاء كل مرحلة:
- `flutter analyze`
- `flutter test`
- manual RTL smoke test
- offline smoke test

لا تعتبر feature مكتملة بمجرد أن الشاشة ظهرت.
