# Myfnt 2.12.4 — Step 21G Local Cache Engine

## الهدف
تقليل ضغط التخزين والقراءة المتكررة على الهواتف مع الحفاظ على Offline-First وعدم تغيير عقود الحجز أو المالية أو المزامنة.

## التحسينات المنفذة
- ترقية IndexedDB من schema version 5 إلى 6 بدون تغيير اسم قاعدة البيانات أو خفضها.
- إضافة فهرس `workspace_status` لطابور المزامنة للوصول مباشرة إلى pending/failed/sending/conflict بدل قراءة كل الطابور ثم التصفية في JavaScript.
- إضافة فهرس `workspace_updated` لتجهيز القراءة/الصيانة حسب مساحة العمل والزمن.
- إضافة فهرس `workspace` إلى `local_meta` وترحيل السجلات القديمة تلقائياً أثناء ترقية القاعدة.
- `hydrationSnapshot()` يقرأ UI metadata الخاصة بالـ workspace فقط بدل `getAll()` لكل metadata الموجودة في الجهاز.
- `setUiMeta()` يتجنب الكتابة عندما تكون القيمة الجديدة مطابقة للقيمة المحفوظة.
- `safeStorage` أصبح يحتفظ بكاش قراءة داخل الذاكرة ويتجنب `localStorage.setItem()` إذا لم تتغير القيمة، مع إبطال الكاش فور وصول StorageEvent من تبويب آخر.
- تنظيف تلقائي خفيف أثناء idle لطابور المزامنة النهائي، مع الاحتفاظ بآخر 300 سجل synced/superseded فقط.
- إزالة JSON القديم الكبير للحجوزات/السندات/العملاء من localStorage فقط بعد إثبات وجود نسخة IndexedDB طبيعية، حتى لا يتم حذف النسخة الوحيدة الباقية أبداً.
- تحسين Service Worker: الصفحة الرئيسية Network-First، الملفات JS/CSS ذات `?v=` Cache-First، وبقية الملفات الثابتة Stale-While-Revalidate.
- تغيير Cache name للإصدار الجديد مع تنظيف كاش نسخ Myfnt الأقدم لنفس المسار فقط.

## الأثر المتوقع
- فتحات أسرع بعد أول تحميل خصوصاً على شبكات الهاتف البطيئة.
- عدد أقل من عمليات القراءة والكتابة على localStorage وIndexedDB.
- منع تضخم sync_queue على الأجهزة طويلة الاستخدام.
- تقليل احتمال jank عند فحص/تشغيل المزامنة مع عدد كبير من العمليات السابقة.
- بقاء Offline-First بنفس السلوك الحالي وعدم اعتماد نجاح الحفظ على الشبكة.

## اختبارات ثابتة
- `node --check` مر على ملفات JavaScript المعدلة وكل ملفات JS الأساسية بدون أخطاء Syntax.
- تطابق Cache-Busters بين index.html و service-worker.js للملفات المعدلة.
- الإصدار موحد إلى 2.12.4 في core/manifest/index/service worker.
- تجربة Chromium داخل الحاوية لم تُظهر أخطاء JavaScript من التطبيق؛ انتهت بسبب قيود بيئة DBus/zygote للحاوية وليست أخطاء تطبيق.
