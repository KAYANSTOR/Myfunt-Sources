# Myfnt 2.10.8 — Step 21D

## الهدف
نقل عرض الشهر الرئيسي والتقويم تدريجيًا من المسح الكامل لمصفوفة الحجوزات في RAM إلى Query Layer مفهرسة على IndexedDB، مع إبقاء بقية الشاشات دون تغيير لتسهيل الاختبار.

## ما تم
- إضافة `MyfntQuery.bookingsMonthView(year, month)` لإرجاع نموذج عرض متوافق مع بطاقات الحجز من `bookings + booking_details`.
- إضافة `MyfntMonthData` كـ cache صغير للشهر المعروض فقط.
- بطاقات الرئيسية تعتمد على بيانات الشهر من IndexedDB بعد التحميل.
- CalendarCore يستخدم بيانات الشهر الحالية بدل كل حجوزات السنة متى كانت Query جاهزة.
- نافذة حجوزات اليوم تستخدم بيانات الشهر نفسها.
- عند تغيير الشهر يتم طلب الشهر الجديد فقط.
- عند Hydration أو تعديل الحجوزات يتم إبطال cache وإعادة تحميل الشهر الحالي.
- لا تغيير على الحفظ أو المالية أو Outbox أو بروتوكول المزامنة.

## ملاحظة انتقالية
بقية الأنظمة مثل مركز التنبيهات والبحث العام ما زالت تستخدم Repository/RAM في هذه الخطوة. إزالة مصفوفة الحجوزات الكاملة من RAM ستكون بعد نقل هذه المستهلكات واحدًا واحدًا واختبارها.

## اختبار
1. فتح التطبيق وإظهار بطاقات الشهر دون لمس التقويم.
2. الانتقال بين 3 أشهر ذهابًا وعودة.
3. النقر على يوم فيه أكثر من حجز.
4. إضافة حجز في الشهر الحالي ومشاهدة ظهوره مباشرة.
5. تعديل/إلغاء حجز ومشاهدة تحديث البطاقات والتقويم.
6. إغلاق التطبيق وفتحه مجددًا.
